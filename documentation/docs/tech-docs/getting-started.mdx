# Начало работы

---

## Что такое in-Cloud?

**in-Cloud** — это фреймворк для создания собственного пользовательского интерфейса поверх Kubernetes API. Вы можете создать интерфейс, соответствующий вашему видению — от минималистичного дашборда до полноценного решения в стиле OpenShift Console. Все элементы собираются из готовых компонентов, а логика описывается декларативно.

---

## Установка in-Cloud Console

На этом этапе вы устанавливаете основное приложение. Можно развернуть как базовую конфигурацию, так и полную версию с `oAuth-Proxy` и `Dex`.

На этом же шаге добавляется UI-слой — готовый пресет, который станет удобной отправной точкой для знакомства с системой.

<CodeBlock language="bash">
  {dedent`
    helm upgrade in-cloud-web oci://registry-1.docker.io/prorobotech/incloud-web-chart  \\
      --version=1.3.0-9b1cdc4 \\
      --namespace in-cloud-web \\
      --install \\
      --set incloud-web-resources.enabled=false \\
      --set fullnameOverride=in-cloud-web \\
      --create-namespace
  `}
</CodeBlock>

## Как начать использование

Мы понимаем, что каждая инфраструктура отличается, включая способ экспонирования трафика (`Ingress`, `VirtualService` и так далее). Поэтому эту часть мы оставляем на вашу собственную настройку.

По умолчанию создаётся один `Deployment` с тремя контейнерами: `Nginx`, `Web` и `BFF`. Входящий трафик необходимо направить на контейнер `Nginx` на порт `nginx-http`.

Для быстрого старта можно использовать `port-forward`:

<CodeBlock language="bash">
  {dedent`
    sudo kubectl port-forward svc/in-cloud-web 80:80 -n in-cloud-web --kubeconfig ~/.kube/config
  `}
</CodeBlock>

После этого откройте [http://localhost:8081](http://localhost:8081) в браузере.
Вы увидите стандартный интерфейс **in-Cloud Console**: начальную версию UI с предварительно настроенным сайдбаром и несколькими стандартными страницами, такими как списки `Namespaces`, `Workloads` и сервисов.

Эта конфигурация предназначена только для ознакомления и локальной отладки.
В продакшн-среде трафик должен быть экспонирован через ваши стандартные механизмы, такие как `Ingress` или `Istio VirtualService`, а доступ должен быть интегрирован с вашим провайдером идентификации.

:::info RBAC
Если установка используется для ознакомительных целей, необходимо добавить привязку роли для анонимного пользователя.
В Kubernetes все пользователи, не прошедшие аутентификацию, автоматически назначаются субъекту `system:anonymous`.

<CodeBlock language="yaml">
  {dedent`
    ---
    apiVersion: rbac.authorization.k8s.io/v1
    kind: ClusterRoleBinding
    metadata:
      name: anonymous-clusterrolebinding
    roleRef:
      apiGroup: rbac.authorization.k8s.io
      kind: ClusterRole
      name: admin-clusterrole
    subjects:
      - kind: User
        name: system:anonymous
        apiGroup: rbac.authorization.k8s.io
  `}
</CodeBlock>
:::
